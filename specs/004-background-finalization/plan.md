# План реализации фоновой финализации

**Ветка** `refactor/add-fisrt-containerization` · **Дата** 24 ноября 2026 · [Спецификация](spec.md)

## Подход

Добавить `finalization-worker` как седьмой сервис Compose. STT завершает захват и передаёт долговременный пакет входов. Аналитика владеет заданиями в PostgreSQL и экспортом XLSX. Обработчик получает задания по внутреннему HTTP, читает проверенные входы из S3, запускает итоговый проход Whisper и передаёт структурированные ответы аналитике.

## Технический контекст

- Java 17, Maven, Spring Boot для существующих API и новый небольшой Java-процесс для обработки. Используем имеющиеся клиенты Whisper и S3, разметку ответов, скоринг и генерацию XLSX.
- PostgreSQL и Flyway для снимков, заданий и контрольных точек. Приватный S3 для WAV, журналов, транскрипций и XLSX. Долговременный том STT служит очередью передачи.
- Docker Compose на Linux/amd64, интерфейс на localhost. Один рабочий процесс в пилоте. База атомарно закрепляет задание за попыткой, чтобы два процесса могли безопасно читать одну очередь.
- HTTP/WebSocket, Maven, Node и Python проверяются существующим CI. Новые интеграционные проверки используют PostgreSQL, S3 и управляемые ответы Whisper/FRIDA. Локальный дымовой прогон использует реальные модели и неперсональный двухканальный сигнал.
- Готовность записи и готовность результата измеряются отдельно. STT не ждёт полного Whisper или XLSX для передачи задания. Уровни параллелизма и задержки будущего Kubernetes не входят в критерии пилота.

## Проверка принципов проекта

Публичные маршруты и ссылки сохраняются, новое состояние добавляется без изменения формата старых артефактов. Для внутренних HTTP и изменений событий обновляются контракты. Модели и секреты остаются вне Git. Тестируем потерю подтверждения и перезапуск на границах обработки. Документация и Javadoc на русском. Изменение границ компонентов отражается в исходнике и PNG схемы C4. Решения и результаты фиксируются в журнале.

## Порядок работ

1. **Схема задания и контракты.** Добавить Flyway-миграцию и репозиторий заданий в аналитику, тесты постановки, выдачи, истечения аренды и повтора после перезапуска. Согласовать формат снимка и входов.
2. **Передача из live-сеанса.** До подтверждения `prepare_final` аналитика сохраняет снимок. STT закрывает WAV и журнал, фиксирует роли и Vosk, долговременно ставит на доставку весь пакет и маркер завершения. Аналитика делает задание доступным после проверки комплектности. Для профиля Compose передача заменяет расчёт отчёта в live-потоке. Локальный режим сохраняет прежний путь.
3. **Обработчик и оценка.** Переиспользовать чтение журнала, Whisper и сборщик ответов. Аналитика собирает отчёт из снимка и исходной версии банка. Обработчик поддерживает продление аренды и повтор, используя уже подготовленные результаты.
4. **Публикация и интерфейс.** Фиксировать подготовленный результат до канонической публикации. Повторять публикацию тех же байтов и выставлять «готов» только после подтверждения XLSX. Отдельно отображать восстановление и окончательную ошибку.
5. **Сборка и запуск.** Добавить образ и сервис без публичного порта. Обновить `scripts/start-pilot.ps1` для сборки и проверки готовности. Сохранить существующий `.env` и тома, обработать конфликт `WHISPER_MODEL` с путём Windows в текущем окружении.
6. **Приёмка и PR.** Проверить целостность двух каналов, прежний ID, смену банка, прерывание обработки и повтор публикации. Обновить README, инструкцию, C4 и журнал. Отправить изменения в текущую ветку и обновить существующий PR № 9 в `master`, если он открыт. Слияние остаётся за пользователем после ручного прогона.
