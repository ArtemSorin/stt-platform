# Сквозная приёмка после реализации

## Запуск

Запустить Docker Desktop, открыть PowerShell 7 в корне репозитория и выполнить `pwsh -File ./scripts/start-pilot.ps1`. Если PowerShell 7 уже открыт, допустимо выполнить `./scripts/start-pilot.ps1`. При сообщении «pwsh не распознано» установите PowerShell 7: Windows PowerShell 5.1 не поддерживается. Проверить `docker compose ps` и открыть http://127.0.0.1:8080/. Первый запуск скачивает модели. При обновлении использовать прежние `.env` и тома.

## Основной сценарий

Провести двухканальное интервью с неперсональной контрольной записью и одним подтверждённым ответом. Нажать «Завершить интервью», дождаться подтверждения постановки задания, сохранить ссылку и закрыть вкладку. Открыть ссылку заново, дождаться готовности. Проверить WAV с обоими каналами, ZIP-транскрипцию с ролями и XLSX с ожидаемым вопросом и ответом. Сравнить версию банка до и после новой публикации.

Для детерминированной проверки разбора двухканальной записи, сопоставления ответа и Vosk-резерва используйте Maven-тест `FinalizationTranscriberTest` и тест `LiveInterviewTest`. У них подменён только ответ Whisper; аудиоканалы, журнал, восстановление ответа и построение результата проходят через production-код.

Контейнерную приёмку с реальным S3 и контролируемыми HTTP-ответами запускает `python scripts/test-finalization-worker.py --image finalization-worker:ci` (требуется `boto3`, Docker и собранный образ). Она убивает обработчик во время запроса Whisper, отключает S3 на следующей попытке, теряет подтверждение регистрации XLSX и подтверждение готовности, затем проверяет число попыток, содержимое отчёта и транскрипции, SHA-256 всех результатов и очистку `staging/`. Запуск этого теста входит в CI.

Для дополнительной проверки реальных STT и Whisper используйте неперсональную WAV-запись PCM16 mono 16 кГц: `python scripts/smoke-finalization.py <путь-к-записи.wav>`. Скрипт создаёт тестовое интервью, отправляет речь, завершает его без браузера и проверяет, что транскрипция и XLSX доступны по прежнему ID и содержат распознанный ответ. Для стенда на другом адресе задайте `STT_SMOKE_BASE_URL`, например `$env:STT_SMOKE_BASE_URL='http://127.0.0.1:18080'`. Этот тест использует `/api/test` в моно-режиме без диаризации; он дополняет, но не заменяет ручное двухканальное интервью через браузер.

## Восстановление

1. Во время запроса Whisper остановить контейнер `finalization-worker`, пока задание находится в работе. Пересоздать контейнер и дождаться окончания аренды. Проверить, что готов один XLSX по прежнему ID.
2. На тестовом стенде прервать работу после записи XLSX в S3 до подтверждения в реестре, затем потерять HTTP-подтверждение `complete`. Запустить повтор. Проверить совпадение SHA-256 всех результатов с манифестом, неизменную регистрацию по ключу и очистку временных объектов. Это автоматизировано в `scripts/test-finalization-worker.py`.
3. Выключить S3 перед завершением звонка. Проверить исходники в постоянной очереди STT и статус ожидания. Вернуть S3, дождаться одного набора файлов.
4. Проверить миграцию на старом архиве и отсутствие автоматической постановки для старого интервью. Остановить стенд командой `docker compose down`, сохраняя тома.

Модульные и PostgreSQL/S3-тесты проверяют снимок, очередь, аренду, повтор, конфликтующие манифесты, контрольные суммы и отсутствие автоматической постановки старых интервью. Тест контейнера автоматизирует рестарт во время Whisper, недоступность S3 и повтор публикации. Полное интервью с реальными моделями остаётся ручным сквозным прогоном: тестовый endpoint `/test.html` работает в моно-режиме и не заменяет двухканальный вызов.
