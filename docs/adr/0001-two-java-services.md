# ADR-0001: два запускаемых Java-сервиса

- Статус: принято
- Дата: 2026-10-27

## Контекст

Репозиторий содержал gateway, STT, диаризацию и аналитику как четыре Spring Boot приложения. Gateway только связывал браузер, аудиопотоки и аналитику; Vosk и Nemotron/CAM++ обрабатывали один и тот же входной звук в отдельных приложениях. Это усложняло запуск локального демо и передачу аудио между процессами.

## Решение

Объединить браузерный API, Vosk, Nemotron/CAM++ и оркестрацию аудио в `stt-service` на порту 8080. Оставить `analytics-service` на 8083 для вопросов, решений, FRIDA и отчётов. `common` остаётся общей библиотекой. Python helper-процессы Whisper и FRIDA запускаются отдельно только при необходимости и не считаются Spring Boot микросервисами проекта.

## Последствия

- Браузер передаёт PCM в один STT endpoint; внутренняя фильтрация кандидата выполняется до передачи текстовых событий аналитике.
- В analytics не передаётся бинарное аудио.
- Основной браузерный сценарий использует запись эталона и диаризацию. `/test.html` остаётся изолированным тестом аналитики и явно принимает весь микрофонный звук за речь кандидата.
- STT и analytics запускаются локально на loopback; их внутренний WebSocket дополнительно защищён общим токеном.
- Требования к нативным библиотекам и ресурсам моделей концентрируются в STT-процессе.

## Альтернативы

- Оставить gateway и diarization как отдельные процессы: отклонено, поскольку основная цель — два запускаемых микросервиса и единый владелец аудио/ролей.
- Передавать PCM в analytics: отклонено, поскольку это размывает границу ответственности и увеличивает связанность сервисов.
