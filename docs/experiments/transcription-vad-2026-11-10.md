# Фильтрация тишины в итоговой транскрипции — 10 ноября 2026

В демо 6 ноября зафиксированы повторяющиеся ложные фразы Whisper на длинной тишине. Задача этой проверки — убрать такие участки из входа итогового Whisper-прохода, сохранив короткую и тихую речь.

## Реализация

- Python-помощник принимает `/transcribe-json-vad` с тем же JSON-ответом, что у `/transcribe-json`. Новый путь включает Silero VAD с `threshold=0.5`, `min_silence_duration_ms=2000` и `speech_pad_ms=400`; старый путь оставлен для live-уточнений без VAD.
- После интервью оба канала проходят VAD отдельно. Времена слов остаются привязанными к исходной шкале записи.
- Java сопоставляет слова с признаками речи `SpeechEvidence` того же канала по заданному `minimumOverlap`. Непокрытые интервалы объединяются, если их контексты по 500 мс пересекаются, и повторно отправляются без VAD.
- Если повтор не восстановил слово, интервал остаётся в `gaps` и использует текущий резерв Vosk либо отметку о нераспознанном аудио.
- CPU-зависимость VAD закреплена как `onnxruntime==1.23.2`. Настройка Windows устанавливает её вместе с Whisper командой `pip install -r stt-service/whisper/requirements.txt`.

## Проверки

- Python-тесты помощника: 4 пройдены; проверены оба JSON-пути, одинаковый формат ответа, выбор VAD-параметров и обычный режим без фильтра.
- `mvn verify`: 188 тестов пройдены.
- Javadoc для сервисов: пройден.
- JavaScript-тесты: 16 пройдены.
- Python-тесты FRIDA: 5 пройдены, 1 пропущен из-за отсутствующего необязательного пакета `frida_decisions`.
- Redocly CLI 1.34.2 проверил четыре OpenAPI-контракта; все прошли.
- Первый полный Maven-прогон выявил устаревшие тестовые заглушки старого endpoint. После их обновления полный прогон прошёл.

## Ограничения и следующий шаг

Предоставленные материалы демо содержат конспект и транскрипцию, но не WAV. Поэтому реальная проверка сохранения тихих и коротких фраз пока не выполнена; автоматические тесты проверяют маршрутизацию и повтор без VAD на моках.
