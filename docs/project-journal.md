# Журнал проекта AI-референт

## Нативный STT на ARM и универсальный запуск — 26 ноября 2026

- Быстрый запуск теперь поддерживает Windows PowerShell 5.1/7 и POSIX `sh` для macOS/Linux. Скрипты создают `.env` один раз, временно снимают `COMPOSE_FILE`, `COMPOSE_PATH_SEPARATOR` и `DOCKER_DEFAULT_PLATFORM`, не передают путь Windows в Linux `WHISPER_MODEL`, и ждут HTTP STT вместе со здоровьем `finalization-worker`.
- Сохранена распаковка Linux runtime через `bsdtar`, так как на Mac ранее `tar` завершался сообщением `Function not implemented`. Архитектура STT выбирается без override: x86_64 или aarch64. Для ARM64 используются нативные NeMo, sherpa-onnx и дополнительный официальный Vosk runtime; каждый скачиваемый бинарный артефакт проверяется SHA-256.
- Добавлены проверки образа и запуска STT на CI runner-ах `amd64` и `arm64`, smoke-запуск диаризации и Vosk, а также проверка Compose образов PostgreSQL/SeaweedFS и приложения на обеих архитектурах. Сквозная нагрузка на реальном Mac остаётся обязательной ручной проверкой.
- Локально после совмещения с актуальным PR HEAD прошли полный `mvn verify` (включая `finalization-worker`), 18 Node-тестов, тесты Whisper helper (4) и FRIDA helper (5, один пропущен из-за отсутствующей необязательной модели), Redocly по четырём контрактам, Compose config, PowerShell smoke в 5.1/7 и Bash smoke. Нативная сборка Linux-образов будет подтверждена CI; этот Windows-хост не является проверкой скорости ARM на Mac.
- Лог пользователя показал `queue_overflow`, после которого браузер получил HTTP 409 и обработал его как потерю источника: он остановил захват и отправил `capture_error`. Поэтому итоговый этап пометил полную запись недоступной. Очередь подтверждает отставание live-диаризации; предупреждение ONNX `Unknown CPU vendor` само по себе не доказывает причину. По архитектуре контейнера и метрикам `summary.json` нужно отдельно определить, использовалась ли эмуляция и насколько inference отставал от реального времени.
- Очередь live-диаризации теперь деградирует отдельно: после переполнения Nemotron завершает уже принятые кадры, последующие кадры учитываются как пропущенные только для ролей, а `SessionManager` продолжает передавать полный системный звук и микрофон в запись/STT. Фаза `degraded` не завершает интервью; пользователь может продолжить вопросы и обычным действием запустить финализацию. UI предупреждает, что роли могут быть неполными. Реальная потеря аудиодорожки остаётся отдельной ошибкой и помечает полную транскрипцию недоступной.
- Добавлены тесты очереди на однократный переход при переполнении и учёт отброшенных кадров, а также проверка, что в `degraded` принимаются оба аудиоканала и команды интервью без пометки источника потерянным.

## Фоновая финализация интервью — 24 ноября 2026

- Реализация `finalization-worker` завершена: снимок live-интервью фиксируется до подтверждения финального шага; аналитика ставит постоянное задание после регистрации полного архива; обработчик арендует его, распознаёт оба канала, восстанавливает ответы и публикует единый манифест XLSX/транскрипций. Состояния звонка, записи и отчёта разделены; ручной перезапуск стенда не сбрасывает очередь.
- Для повторов оставлены неизменяемый манифест и канонические ключи объектов. После потерянного ответа `complete` обработчик сверяет сохранённое состояние и манифест через внутренний status API, после чего убирает staging. При исчерпании повторов разрешён явно помеченный Vosk-резерв только при полном покрытии каналов; иначе задание остаётся ошибочным и исходная запись сохраняется.
- Проверки 24 ноября: `mvn verify` прошёл; JavaDoc сгенерирован; 18 Node-тестов прошли; Whisper helper — 4 теста, FRIDA helper — 5 пройдено и 1 пропущен из-за отсутствующей необязательной модели; все четыре OpenAPI-контракта прошли Redocly. Одноразовые PostgreSQL 17.6 и SeaweedFS прошли миграции V1–V3, тесты очереди, конкуренции аренды, истечения аренды, идемпотентной регистрации и восстановления.
- Linux-образ `finalization-worker` собран. Контейнерный отказный тест с реальным SeaweedFS и контролируемыми HTTP-зависимостями прошёл: остановка во время Whisper, отказ S3, повтор регистрации тех же байтов, потерянный ответ готовности, сверка SHA-256, XLSX и транскрипции, удаление staging. Тестовая очередь учитывает `retry_wait`, поэтому результат не зависит от гонки таймеров.
- Быстрый старт и `docker compose config` проверены, Compose содержит семь сервисов; синтаксис PowerShell проверен. Существующий активный пилот и его тома не перезапускались и не менялись. Полное браузерное двухканальное интервью с реальными моделями остаётся ручной приёмкой перед слиянием; шаги и необязательный моно-smoke описаны в [quickstart](../specs/004-background-finalization/quickstart.md).
- Коммит `4d2c26d` отправлен в `refactor/add-fisrt-containerization`; открытый PR [#9](https://github.com/ArtemSorin/stt-platform/pull/9) направлен в `master` и содержит этот коммит. Изменение описания PR и публикацию комментария блокирует GitHub-интеграция с ответом `403 Resource not accessible by integration`; страница PR в доступном браузере открылась без авторизации. Сценарий ручной приёмки уже находится в quickstart и в изменениях ветки. Метаданные PR требуют обновления после восстановления write-доступа.
- CI для PR обнаружил, что контейнер восстановления на Linux не доходил до Whisper: тестовый S3 был опубликован только на loopback хоста, тогда как worker шёл через host-gateway. Тест переведён на отдельную Docker-сеть с внутренним DNS-именем SeaweedFS; порт для тестового процесса остаётся на loopback. Изолированный recovery-тест после исправления прошёл.
- Интеграционная матрица также выявила зависимость `CatalogStoreTest` от порядка тестов: очистка возвращает и уже помеченные объекты всей общей схемы. Проверка бессрочного хранения теперь проверяет только интервью, созданное этим тестом.

### Ранние заметки о ходе реализации

- Начата реализация: подготовлены миграция, постоянная очередь с арендой и сохранение снимка фактически заданных вопросов и ответов. Проверены сериализация снимка, конкурентная выдача задания и повтор после истечения аренды. Сквозной путь с обработчиком и публикацией XLSX ещё разрабатывается.
- Добавлена подготовка пакета и повторная доставка запроса на постановку задания после регистрации входов; этот путь пока выключен. Во время ожидания и обработки снимок защищает архивное аудио от удаления по сроку хранения. Для будущего обработчика добавлены проверка WAV и повторное открытие PCM с сохранением каналов. На PostgreSQL 17 проверены неполный пакет, истечение аренды и защита аудио; проверка готовности требует совпадения хеша и размера XLSX с манифестом. Сквозная проверка и сам контейнер ещё не реализованы.

- Подготовлены [спецификация](../specs/004-background-finalization/spec.md), [план](../specs/004-background-finalization/plan.md) и [задачи](../specs/004-background-finalization/tasks.md). Работа планируется в `refactor/add-fisrt-containerization`.
- Сейчас STT запускает завершение в своём процессе. Итоговая оценка опирается на активный WebSocket и состояние аналитики. WAV может сохраниться раньше, чем данные, нужные для повтора.
- Запланированы долговременная передача снимка и записи, выдача заданий с арендой из PostgreSQL и повтор публикации тех же байтов. Готовность отчёта проверяется отдельно от состояния записи.
- В приёмку входят закрытие страницы, остановка обработчика во время Whisper, потеря подтверждения публикации, повторный запуск и чтение старых ссылок. Быстрый запуск должен сохранить локальные секреты и корректно обработать переменную модели Whisper с Windows-путём.

## STT в Linux-контейнере — 23 ноября 2026

- [Спецификация и план](../specs/003-linux-stt/spec.md). Контейнер на CPU x86_64, Vosk small, NeMo-Speech.cpp 0.3.0 и sherpa-onnx JNI 1.13.8. Слои моделей проверяются по SHA-256.
- Первая загрузка с JitPack закончилась тайм-аутом. Linux JNI теперь поступает из релиза с проверкой суммы. Другая копия CAM++ имела отличный SHA-256, поэтому выбран снимок, совпадающий с Windows.
- Контрольный прогон фрагмента русской речи: Vosk вернул слова, Nemotron выделил сегмент, CAM++ подтвердил сходство с эталоном 0,9897. Точность и задержка на выборке интервью не оценивались.
- WAV и XLSX получены по ID. При выключенном SeaweedFS статусы были pending, после перезапуска STT и восстановления SeaweedFS — saved и ready. Системный PCM совпал с исходным побайтно. Дополнительный прогон с непустыми обоими каналами сравнил их с исходным сигналом.
- При отключённом S3 пересоздан контейнер STT с ожидающей очередью. После восстановления S3 оба разных канала WAV совпали побайтно с отправленными, в реестре по одному WAV и XLSX. Приёмка реального звонка с двумя участниками и сравнение Windows и Linux остаются открытыми. Whisper, FRIDA и фоновый обработчик входят в следующую работу команды.


## Архив интервью — 23 ноября 2026

- [Спецификация архива](../specs/002-interview-archive/spec.md); [запуск и ограничения пилота](archive-pilot.md).

При выключенном и при недоступном Whisper XLSX и WAV сохранились; при отключённом SeaweedFS оба статуса оставались ожидающими, после перезапуска STT и аналитики и восстановления хранилища запись и отчёт стали доступны. Проверены формат WAV, содержимое обоих каналов и сигнатура XLSX. Тест не оценивает качество распознавания.

- Следующие этапы: проверка Linux-совместимости моделей, персональные права, контрольные точки аудио во время интервью, воспроизводимая фоновая финализация и Kubernetes. Потеря узла до загрузки не покрывается.

# Запуск на разных системах — 25 ноября 2026

При пробном запуске на Apple Silicon сборка amd64 STT остановилась на распаковке NeMo через GNU tar. Для распаковки используется bsdtar, STT явно собирается для linux/amd64; на Apple Silicon необходима эмуляция. Добавлен скрипт для macOS и Linux с созданием секретов и ожиданием готовности. На Windows образ STT собран, семь контейнеров запущены, повторный запуск shell-скрипта проверен; изолированный тест создания и сохранения конфигурации прошёл в Linux-контейнере. Требуются проверка на реальном Mac и проверка двухканального захвата браузером; эмуляция может влиять на скорость обработки.

## Проверка Mac и работа над ARM — 26 ноября 2026

На Mac пользователя семь сервисов запустились после изменения внешнего порта объектного хранилища: 8333 был занят SSH-туннелем. В Compose доступ к S3 теперь предусмотрен только внутри сети, что устраняет этот конфликт; пересоздание хранилища проверено локально. Для сокращения затрат на эмуляцию подготовлена экспериментальная сборка STT для Linux ARM64 с нативными NeMo, Sherpa и Vosk. Необходимо проверить распознавание и производительность на реальном ARM. Сам запуск Mac не подтверждает захват обоих каналов и качество интервью.

ARM-образ собран и запущен под эмуляцией: Vosk загрузил модель, а NeMo и Sherpa создали сессию и обработали синтетический эталон. Сборка amd64 и запуск полного стенда на Windows также прошли. На реальном Apple Silicon ещё нужен прогон со звуком и оценка задержек; в CI добавлена проверка инициализации для обеих архитектур.

### Обновление копии на Mac

При обновлении локальная ветка Mac не смогла перейти с `f180856` на `8512ba9`: Git сохранил незакоммиченную правку `compose.yaml` и остановил `git pull`. Следующая команда запуска была выполнена отдельно и подняла стенд из старого checkout. Сообщение «Стенд готов» подтверждает запуск прежней версии, но не проверяет новую нативную ARM-сборку. В README добавлена процедура обновления через stash только для `compose.yaml`, fast-forward pull и очистку возможных `COMPOSE_FILE`/`DOCKER_DEFAULT_PLATFORM` в текущей оболочке. Для подтверждения ARM остаётся повторно запустить обновлённый стенд и проверить `uname -m` внутри `stt-service` и реальное двухканальное интервью.

### Исправление CI-сборки STT — 26 ноября 2026

Первый CI-прогон после добавления матрицы amd64/arm64 выявил ошибку Dockerfile: `mvn package` запускался до копирования исходников. Сборка STT включает тестовый classifier `integration-test-classes` из `analytics-service`, поэтому Spring Boot repackage завершался ошибкой отсутствующего main class на обеих архитектурах. Исходники common, analytics и STT перенесены перед Maven reactor-сборкой. Локальный `docker buildx build --platform linux/amd64 --target build` после исправления завершился успешно; полный образ и нативный arm64 runtime ожидают повторного CI-прогона. Очередь аудио в коде не увеличивалась: для ответа на `queue_overflow` нужно измерить задержки на реальном Apple Silicon и выполнить двухканальное интервью.

## Возобновляемая загрузка моделей STT — 26 ноября 2026

- На Mac пользователя сборка stt-service оборвалась при получении Vosk с Hugging Face примерно на 90%: curl сообщил "OpenSSL SSL_read ... unexpected eof while reading" и завершился с кодом 56. Это сетевой обрыв, а не ошибка ZIP-архива или контрольной суммы.
- Загрузки STT переведены на общий проверяемый загрузчик: повтор до 10 раз для сетевых ошибок, продолжение файла через HTTP Range и проверка SHA-256 перед использованием. BuildKit cache mount хранит частичные и завершённые проверенные артефакты между сборками; кэш разделён по архитектуре.
- Первый тест показал, что встроенный curl retry отбрасывает частичный файл. Повтор теперь организован оболочкой вокруг отдельных вызовов curl: каждый следующий вызов считывает смещение частичного файла и запрашивает остаток по Range.
- Добавлен изолированный тест локальным HTTP-сервером: первое соединение обрывается посередине, повтор запрашивает остаток и затем использует проверенный кэш без нового сетевого запроса.
- В руководстве быстрого запуска описано повторение запуска и сохранение BuildKit-кэша. Тест локального HTTP-сервера прошёл; полная Docker-сборка STT для amd64 на рабочей машине завершилась успешно, Vosk, Nemotron и CAM++ проверены по закреплённым SHA-256. CI дополнительно соберёт оба целевых образа и выполнит smoke-проверки.

## Продолжение интервью при перегрузке диаризации

- На Mac ARM обработка 0,64 с звука занимала в среднем 596 мс, p95 — 1738 мс; очередь из 32 фрагментов переполнилась. Ёмкость по умолчанию увеличена до 128 входных фрагментов, чтобы сглаживать кратковременные пики.

## Универсальный быстрый запуск — 26 ноября 2026

- README и новая [инструкция быстрого запуска](quickstart.md) дают отдельные пошаговые команды для macOS, Linux и Windows. macOS/Linux используют один POSIX `sh`-скрипт, Windows — PowerShell; на Windows с отсутствующим `pwsh` запускается встроенный `powershell`. Это сохраняет короткий запуск без установки дополнительной оболочки.
- Оба launch-теста теперь работают во временном каталоге с пробелами и кириллицей и проверяют Windows-путь модели, заданный как переменная окружения и как значение `.env`. PowerShell 5.1, PowerShell 7 и Git Bash прошли тесты; `docker compose config --quiet` подтвердил семисервисный Compose-граф.
- Актуальная ветка до этих документационных и тестовых уточнений имела 18/18 успешных CI-проверок для HEAD `989bb1c`, включая macOS/Linux shell, Windows PowerShell, нативные STT amd64/arm64 и интеграционные проверки. После отправки этого изменения CI должен повторить матрицу.
- На локальном Docker Desktop уже работают контейнеры другого пилотного Compose-проекта и заняты порты 8080/8083. Чтобы не останавливать пользовательский стенд и не рисковать его данными, свежий `compose up` из рабочей копии не запускался. Проверены безопасная конфигурация Compose и изолированные тесты launch-скриптов; полностью чистый старт следует проверять в отдельной среде или после плановой остановки активного стенда.
