# Пилотный архив и запуск

Пилот предназначен для одного компьютера: пользовательские HTTP-порты привязаны к `127.0.0.1`. Все пользователи этого компьютера имеют общий доступ к результатам. Это не аутентификация: не публикуйте профиль в сеть или Kubernetes. Старые локальные результаты не импортируются. По умолчанию записи и отчёты хранятся бессрочно. Для ограничения задайте аналитике отдельно `ARCHIVE_RETENTION_AUDIO_DAYS` и `ARCHIVE_RETENTION_REPORT_DAYS`: `-1` означает бессрочно, положительное целое — срок в днях. Транскрипции и журналы хранятся бессрочно независимо от этих сроков.

## Первый запуск

Команды первого запуска отдельно для macOS, Linux и Windows приведены в [руководстве быстрого запуска](quickstart.md). POSIX-скрипт используется на macOS и Linux; Windows запускает PowerShell-скрипт. Оба создают локальный `.env` со случайными секретами только при первом запуске и поднимают семь контейнеров: STT, аналитику, PostgreSQL, SeaweedFS, Whisper, FRIDA и `finalization-worker`. Скрипты ждут HTTP-готовности STT и статуса `healthy` обработчика, а при ошибке показывают логи. Сохраните `.env` для следующего запуска. Первая сборка загружает runtime и модели. STT выбирает CPU-образы `amd64` или `arm64` по архитектуре Docker Engine. Если `WHISPER_MODEL` содержит путь Windows, скрипт временно использует `small` в контейнере, не переписывая `.env`.

Откройте http://127.0.0.1:8080/ и сохраните ссылку на интервью. После подтверждения постановки задания страницу можно закрыть: та же ссылка покажет состояния звонка, записи и отчёта. Когда отчёт станет готов, по ссылке доступны XLSX и ZIP с транскрипцией. Скачивание обоих файлов закрыто до подтверждения всего набора результатов. PCM и очередь STT находятся в постоянном томе. PostgreSQL, SeaweedFS и очередь отчётов используют отдельные тома. S3 доступен только контейнерам и не занимает порт 8333 хоста. Останавливайте стенд командой `docker compose down`. Команда с `-v` удаляет тома и данные.

Контрольный прогон с неперсональным моно WAV PCM16 16 кГц — `python scripts/smoke-archive.py путь\к\контрольной-записи.wav`. Для проверки Vosk, Nemotron и CAM++ добавьте `--container <имя_контейнера_STT>` и используйте запись с разборчивой речью в первых восьми секундах. Whisper и FRIDA работают отдельными контейнерами и при первом запуске скачивают модели. Вариант запуска STT на Windows описан в [инструкции Windows](windows-setup.md).
## Публикация банка

В чистой базе при старте создаётся версия встроенного командного каталога. После проверки эталонов загрузите новую пару TSV:

```powershell
.\scripts\import-catalog.ps1 -Questions .\analytics-service\src\main\resources\interview\team-questions.tsv -Followups .\analytics-service\src\main\resources\interview\team-followups.tsv
```

Импорт проверяет формат до публикации. Интервью фиксирует текущую версию при старте. Изменение файла после запуска не меняет опубликованную версию и не изменяет старые интервью.

## Сбои и восстановление

Завершение звонка не означает, что архивирование завершено. Статус «сохранена» появляется после загрузки, повторного чтения объекта и записи контрольной суммы в PostgreSQL, а при последующей недоступности S3 сменяется на «хранилище недоступно». Дождитесь состояния «задание принято» и сохраните ссылку: после этого страницу можно закрыть. При недоступности S3 или аналитики очередь остаётся на постоянном диске и повторяет отправку после перезапуска. Не очищайте каталоги очереди и PCM при ожидающем задании. При конфликте объекта проверьте причину, прежде чем вмешиваться в данные; система не заменяет конфликтующий объект.

Задание с истёкшей арендой заберёт следующий обработчик. Подготовленные XLSX и транскрипты закрепляются манифестом до публикации; повтор использует те же байты. После подтверждения готовности обработчик сверяет состояние, включая случай потерянного HTTP-ответа, и очищает временные объекты `staging/`. Логи: `docker compose logs -f finalization-worker analytics stt-service`. [Сценарии приёмки](../specs/004-background-finalization/quickstart.md).

Проверка контейнера с управляемыми Whisper и аналитикой, реальным S3 и симуляцией перезапуска, простоя S3 и потери подтверждений запускается так:

```powershell
python -m pip install boto3==1.40.67
python scripts/test-finalization-worker.py --image finalization-worker:ci
```

Команда создаёт и удаляет отдельные тестовые контейнеры SeaweedFS и обработчика; она не подключается к данным пилота.

Локальная очередь не защищает от потери диска или компьютера до подтверждения архивации, а один контейнер SeaweedFS не является резервной копией. Для пилота с ценными данными нужны отдельные резервные копии PostgreSQL и объектного хранилища с проверкой восстановления. Автоматического продолжения прерванного звонка и персональных прав нет.
