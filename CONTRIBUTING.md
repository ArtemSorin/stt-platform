# Вклад в проект

## Перед запросом на слияние

- [ ] Если изменилось поведение, последовательность вызовов, параметр или ограничение — обновлены README или соответствующий документ в `docs/`.
- [ ] Изменения HTTP-маршрутов отражены в подходящем OpenAPI-файле.
- [ ] Изменения WebSocket-событий, полей, порядка или ошибок отражены в `docs/api/interview-events.md`.
- [ ] Добавлен или обновлён тест для нового поведения.
- [ ] Изменения Java имеют актуальные Javadoc для публичного контракта; реализационные комментарии объясняют только неочевидные причины и ограничения.
- [ ] В Git не попали модели, записи, отчёты, секреты и персональные данные.
- [ ] Пройдены проверки Maven, Node, Python и OpenAPI, затрагивающие изменённую часть.

## Стиль документации и комментариев

Документация проекта пишется на русском языке, кратко и рядом с кодом. Javadoc ставится непосредственно перед объявлением типа или документируемого метода; указываются применимые `@param`, `@return` и `@throws`. Комментарий должен объяснять причину, ограничение или контракт, а не пересказывать следующую строку кода.

OpenAPI-контракты валидируются закреплённой версией Redocly CLI из CI. WebSocket-протокол ведётся в Markdown, поскольку OpenAPI не описывает реальные сообщения этих соединений.
